# 飞书挖掘助手

使用企业自建应用机器人，不使用仅支持群推送的 Webhook。
结果推送复用现有报告 ZIP（对比报告和本次 Bad Case Excel），不上传原始 H5。

## 本机准备

1. 安装项目依赖和 Node.js，然后安装 CLI：`npm install -g @larksuite/cli`。
   Linux 桌面应用需要 CLI 1.0.99 或更新版本。在 `UnifiedApp/packaging` 目录运行
   `bash build_linux.sh`，脚本自动优先查找 `~/.npm-global/bin/lark-cli`、
   `~/.local/bin/lark-cli`，再检查 PATH 中的 CLI；校验后将路径写入打包应用，
   因此双击启动时不会因桌面 PATH
   不同而误用系统旧版；CLI 自身不被打包或复制，需保留在原路径。
   若无 CLI，应用仍可打包，但需要安装新版后重新打包才能固定 CLI 路径。
   当 CLI 被移动或卸载时会明确报错，不会静默切换至旧版；可重新打包或通过
   `MINING_LARK_CLI` 环境变量显式指定新版可执行文件路径。
   对标准 npm 安装，优先使用其同包原生 CLI 二进制，以便关闭应用时直接终止监听进程，
   避免 Node 包装进程退出后遗留卡片消费者。
2. 创建或配置专用应用：`lark-cli config init --new --name datamining-bot`。
   Ubuntu 要绑定到同一个应用，不能再创建第二个机器人；可使用
   `lark-cli config init --name datamining-bot --app-id <已有AppID> --app-secret-stdin`，
   Secret 仅在本机通过标准输入提供，不写入仓库或命令参数。
3. 开启机器人能力，应用权限至少包括 `im:message:send_as_bot`、`im:resource`、
   `im:message.p2p_msg:readonly`；卡片操作另需 `im:message:readonly`（CLI 获取卡片原内容）。
   在“事件与回调”选择长连接，在事件配置添加 `im.message.receive_v1`（接收消息），
   **在回调配置另外开启 `card.action.trigger`（卡片交互回调）**，按飞书要求发布并将本人加入可用范围。
   卡片监听进程已就绪不代表后台已配置回调；缺少回调配置时按钮不能驱动挖掘。
4. 配置本机项目环境并保存 J6B/MMT 预设，特别是本机路径、Python 和日期范围。

## 绑定与启动

在仓库根目录执行：

```bash
python UnifiedApp/feishu_agent.py --bind
```

向机器人私聊发送终端显示的 `绑定挖掘助手 <一次性码>`。绑定成功后，只接受这个
账号在这个私聊中发送的指令。请勿把绑定码发到公开群。

绑定信息保存在 `~/.unified_mining_app/feishu_bot.json`，消息去重保存在相邻 SQLite 文件，
均不含 App Secret。Secret 由 lark-cli 单独保管，不随 Git 同步。绑定后程序继续运行。

所有入口都回传：飞书发起、本机统一界面发起、直接运行 J6B/MMT 的 DataMining.py，
只要成功产生报告，就向本机持久回传队列投递，不要求任务由机器人发起。
统一界面正常生成对比报告时仍回传现有 ZIP；未启用或未成功生成对比报告时，
回传本次原始报告及可用的 Bad Case Excel。直接运行脚本也会自动打包这两类报告。
dry-run、列指标和未产生结果的失败任务不生成结果包。

后续在同一电脑上运行统一界面，会自动启用推送和远程指令。

日常使用只需打开数据挖掘应用，无需另开终端或运行后台助手。
机器人复用应用的任务管理器，在应用启动时自动连接；退出应用时同时停止
机器人监听和发送进程。连接、发送或启动失败会在应用状态栏提示。
首次绑定仍按上面的 `--bind` 步骤完成，未绑定或配置禁用时不会自动联网。

仅在不打开桌面应用、需要独立后台运行时执行：

```bash
python UnifiedApp/feishu_agent.py
```

同一电脑只需一个机器人监听/发送进程，锁文件会阻止重复启动助手。可以同时打开
统一界面或运行命令行挖掘，它们通过本机队列把结果交给已运行的后台助手。
机器人程序和解析电脑必须保持在线；没有助手在线时先保存待发送项，助手下次启动后补发。
不同电脑不要同时监听同一机器人，否则远程指令可能由另一台处理；
更换运行机器时先停止原机器。Ubuntu 还需配置同一应用凭据并重新绑定本人账号。

## 远程操作台

桌面与飞书共用预设及 JobManager 任务队列。远程不会模拟鼠标点击，
不会覆盖桌面正在编辑的表单。保存或删除预设后，对应平台的预设列表自动刷新。
第一版支持 J6B/MMT 的现有表单参数；不提供任意 shell、Python、程序目录、
模板配置或信号映射的远程修改。已有预设的模板由本机设置，其他配置保持继承。

### 本机路径授权（首次使用远程运行前配置）

应用菜单 **设置 → 飞书远程路径设置…** 中配置运行电脑名称及路径别名：

| 别名示例 | 权限 | 本机路径类型 |
| --- | --- | --- |
| MMT数据 | input | 已存在的数据根目录 |
| 挖掘报告 | output | 已存在的输出根目录 |
| 上次发布版本 | report | 已存在的 XLSX 基线文件或报告目录 |

允许直接填写授权根目录内的绝对路径，但不接受未授权路径；相对路径、
`..` 或符号链接不能逃出授权范围。输入 H5 也必须在 input 根目录内。
输出子目录可尚未创建。路径配置只允许在本机应用中修改，不能通过聊天授权新目录。
远程保存时将路径别名转换为绝对路径，保存的预设可直接在桌面使用。
修改路径授权会立即影响后续远程操作，不需要重启机器人。

### 卡片操作（推荐）

使用飞书客户端 7.20 或以上版本；本机数据挖掘应用需要保持打开。
向已绑定机器人发送 **操作台**（或 **菜单**），后续通过按钮和表单操作：

1. 选择 **J6B / MMT 挖掘**，从下拉菜单选择已有预设并编辑，或填写名称新建。
2. 基本参数页预填车型、报告版本、动力形式、日期范围、授权输入/输出目录和自动对比。
   J6B 输入目录支持多选；MMT 另外提供数据软件筛选和两条流水线开关。
   报告软件版本只作报告标签，不等同于 MMT 数据软件筛选。
3. 点击 **高级参数** 编辑报告名称、指标/信号开关、扫描参数、基线和归档目录等。
   切换基本/高级页会先提交当前页到草稿；另存名称同样保留。
4. 点击 **保存 / 另存为**：新名称直接保存；已有名称先展示覆盖确认卡，
   再点 **确认覆盖**。删除预设也需要单独确认。预设修改冲突会明确拒绝，
   请重新打开最新预设后再保存。
5. 点击 **预览运行**，核对参数、目录、模板和队列摘要后，点 **确认运行** 才进入
   桌面共享队列。不需要输入确认码，也不会模拟桌面鼠标操作。
6. 任务卡提供 **刷新状态、查看日志、取消任务、获取结果 ZIP**；取消需要再次确认，
   ZIP 仅在结果已就绪时提供。任务卡是发送时的快照，点击刷新获取最新卡；
   后台仍按原节流规则发送进度文字，结果就绪后自动回传 ZIP。

卡片只提供本机已授权的路径别名，以及当前预设已有路径；已有路径在保存、
预览和确认执行时仍受本机授权检查。增加授权或配置子目录请先在本机完成，
不能通过卡片扩大权限。高级参数和文字指令共用同一套类型、范围及路径校验。

表单和导航卡最长有效 30 分钟，确认卡只有 5 分钟。一次有效点击后会发送下一张卡，
**请在最新卡片继续操作**；旧卡、不同消息中的复制按钮、重复确认、应用重启后的
按钮均不会重复执行。翻页或重新打开预设后，旧编辑卡不能回写草稿。
返回操作台不会提交尚未点击提交按钮的输入；回调校验失败会提示错误并尽量重新发出
最新草稿表单，需要重新填写本次未成功提交的输入。
重启保留草稿，但不保留任何待执行确认；需要重新打开操作台预览。

消息与卡片分别使用同一 CLI 长连接事件总线上的两个监听进程，退出应用时一起停止，
不需要公网服务器或 Webhook URL。只有绑定账号在绑定私聊内的有效卡片回调会被处理，
卡片操作按事件 ID 持久去重，审计只记录操作类别和结果，不记录完整表单或确认码。
不能点击时先检查回调配置、应用发布及权限；也可发送 **帮助** 使用原文字指令。

### 连接故障排查

- 已添加回调但按钮仍无效：确认变更已经发布，不只是保存在开发配置中。
- CLI 显示 `bot: not_configured` 或 `invalid_client`：本机绑定信息不等于 CLI 凭据。
  在本机安全恢复原应用的 `datamining-bot` profile，不要创建另一个机器人，
  不要将 App Secret 发到聊天、写进脚本或提交到仓库。初始化使用
  `config init --name datamining-bot --app-id <原AppID> --app-secret-stdin`，
  Secret 通过标准输入提供；随后用 `--profile datamining-bot auth status --json --verify`
  检查 bot 是否为 ready。
- 回调时间戳：实际 `card.action.trigger` 可返回微秒，尽管 CLI schema 标注毫秒。
  程序按秒、毫秒、微秒三种明确格式解析，再统一执行回调时间窗校验
  （不早于当前 10 分钟、不晚于当前 60 秒），不会为兼容格式而放宽旧卡或确认过期保护。

### 文字指令和使用流程（备用）

名称可含空格，命令中的 J6B/MMT 不区分大小写。示例：

```text
预设 MMT
查看预设 MMT 日常挖掘
编辑预设 MMT 日常挖掘
修改 日期=20261101-20261105
修改 数据软件筛选=V1.2.3
查看草稿
另存预设 MMT 十一月验证
运行草稿
确认运行 <机器人提供的确认码>
```

也可新建空白草稿：

```text
新建预设 J6B 发布验证
修改草稿
输入目录=J6B数据
输出目录=挖掘报告
车型=E2LB
报告软件版本=V1.2.3
日期=20261101-20261105
动力形式=PHEV
自动对比=开启
保存预设
运行草稿
```

多输入目录用英文或中文分号分隔，每个参数独占一行。每次修改是整体校验：
任一参数错误时本次修改全部不生效。布尔值填写 `开启/关闭`（也支持 `true/false`），
动力形式为 `ICE/PHEV/BEV`。日期支持单日或起止范围，起始日期不能晚于结束。
MMT 扫描深度为 0～20，续跑模式为 `auto/never`，至少开启一个流水线。
J6B 指标为 `all` 或逗号分隔的现有指标名；运行前核查是否存在。
空值使用 `参数=`，但运行时仍需满足必填项。

| 指令 | 行为 |
| --- | --- |
| `帮助`、`参数`、`路径` | 查看指令、当前草稿可修改字段、授权路径 |
| `预设 [J6B/MMT]` | 列出本机预设 |
| `查看预设 MMT 名称` | 查看参数，不改变草稿 |
| `编辑预设 MMT 名称` | 复制已有预设到草稿；原预设不变 |
| `新建预设 J6B 名称` | 新建默认参数草稿 |
| `查看草稿`、`清空草稿` | 查看或清除当前草稿，不删除已有预设 |
| `保存预设 [名称]` | 保存为新预设；同名时转入覆盖确认 |
| `另存预设 MMT 名称` | 同平台另存；同名仍需覆盖确认 |
| `覆盖预设` | 展示参数差异，等待 `确认覆盖 <码>` |
| `删除预设 MMT 名称` | 等待 `确认删除 <码>`，只删除预设 |
| `运行草稿`、`运行 MMT 名称` | 校验后返回运行摘要，等待 `确认运行 <码>` |
| `放弃确认` | 作废待确认操作 |
| `任务`、`状态` | 查看本进程最近15个任务 |
| `状态 <任务ID>` | 查看指定任务及打包状态 |
| `取消 <任务ID>` | 等待 `确认取消 <码>`；只取消该任务 |
| `日志 <任务ID>` | 返回最近10行、最多3000字摘要，不上传任意日志文件 |
| `结果 [任务ID]` | 将指定任务或最近的 ZIP 加入持久发送队列 |

任务ID可使用列表显示的短ID；不唯一时拒绝执行，需填写更长的ID。
没有结果包或任务已结束时，不会假装重发/取消成功。
运行预览显示运行电脑、全部表单参数、解析后的路径、继承模板、修改项和当前队列。
默认值以 JobSpec 为准；`新建预设`不会继承桌面未保存的表单。

可修改字段：
- 公共：车型、报告软件版本、动力形式、任务名称、输出目录、自动对比、
  基线报告、对比详情、原始报告保存目录。
- J6B：输入目录、日期、报告名称、启用指标、信号范围、信号图、延迟检查。
- MMT：输入目录、日期、数据软件筛选（别名“软件筛选”）、扫描深度、目录后缀、
  报告名称、文件匹配、CAN流水线、Topic流水线、续跑模式、试运行。

**报告软件版本只是报告标签，MMT 数据软件筛选才用于选取数据；两者不会混用。**
不完整草稿可保存，运行时输入路径及报告必填项须齐全；MMT 试运行沿用原有 dry-run 规则。

### 确认、恢复和冲突处理

运行、覆盖、删除、取消都需一次性确认，确认码5分钟有效。
修改草稿、新建/编辑草稿或新发起另一个确认后，旧确认失效。
运行使用预览时的参数快照；确认时重新校验路径权限、环境及模板。
模板、路径授权或环境发生变化时需重新预览，不能借旧确认运行。
预设覆盖/删除检查文件版本，桌面在此期间修改了预设就拒绝旧操作。
保存采用锁和原子替换，避免桌面与飞书并发写坏文件。

草稿保存到本机 `feishu_bot.remote.json`，应用重启后可恢复；
确认只在内存中保存，重启一律作废，不自动执行。更换绑定账号不恢复旧账号草稿。
远程指令按 message_id 在磁盘去重，并在相邻 SQLite 的 `remote_actions` 表记录
指令类型、接受/失败状态及时间。审计不保存完整聊天内容、确认码或凭据。
任务列表、任务详情及“最近结果”目前仅覆盖本进程，不恢复历史任务。

机器人回传排队、启动、主要进度和结束状态。同一运行状态下每20%一个进度档，
且至少间隔60秒，避免刷屏。结果就绪后沿用持久队列自动发送。
取消主挖掘任务不表示取消其他已独立启动的对比/延迟检查任务，需要按其任务ID分别取消。

只接受绑定账号的本人私聊文本，拒绝群消息和其他账号；过期消息不执行。
应用关闭后不能通过机器人唤醒电脑或启动应用。变更绑定或禁用机器人会停止当前助手，
重新打开应用后才使用新绑定，防止旧队列发给新账号。

ZIP 打包完成后，不论任务来源，都会持久化到相邻的 `.outbox.sqlite3` 队列。
助手每 3 秒检查一次，通过独立子进程上传文件和发送消息，避免阻塞主界面。
每次发送失败最多立即重试 2 次；仍失败则保留队列并逐步延长重试间隔（最多一小时）。
重启后补发、同一产物去重；更换绑定账号不会把旧队列发给新账号。本地 ZIP 始终保留。
可用 `UNIFIED_MINING_DISABLE_PUSH=1` 临时禁止当前进程投递（例如自动化测试）。
文件大小与网络限制以飞书返回为准，不能发送时不会把结果自动转存到其他外部网站。

如本机无法找到 CLI，可用 `MINING_LARK_CLI` 指定原生可执行文件路径。
停止推送和远程控制：退出助手，并将本机配置中的 `enabled` 设为 `false`。
